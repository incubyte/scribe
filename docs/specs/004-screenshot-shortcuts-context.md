## 2. Patterns to follow
- **Adapter crate gated by target.** The OS deps go under `[target.'cfg(target_os = "macos")'.dependencies]` and each module carries `#[cfg(target_os = "macos")]`. The crate still compiles empty on Linux CI. See `audio-macos/Cargo.toml` + `lib.rs` and `audio-windows/lib.rs`. Unsafe code is `#![allow(unsafe_code)]` per file (`tap.rs`, `bridge.rs`); the workspace denies it.
- **Wiring per OS at the tray composition root.** `lanes.rs` has `mod macos` / `mod windows`, each with a `pub use` of the same names. Mirror this for the capturer.
- **Pure core + a try/notify shell in the tray.** `mcp_clipboard.rs` (`copy_config` → `try_copy_config` → a `thiserror` enum with `#[from]`), then `notifications::notify_*`. One outcome maps to one notification.
- **Work off the main thread.** `recording::start_in_background` uses `thread::spawn` and reports failure, and `notifications::system_settings` spawns a thread because `mac_notification_sys::send` blocks until the user responds.
- **Settings.** Tray-only keys are private `const`s beside their user, e.g. `privacy.rs` `ACKNOWLEDGED_KEY`. Read with `app.store(SETTINGS_FILE_NAME).ok().and_then(|s| s.get(KEY)).and_then(as_…).unwrap_or(default)`, then `set` + `save()`. `SETTINGS_FILE_NAME` comes from `store_markdown`.
- **IPC contract.** Rust commands are snake_case verbs or nouns (`change_transcripts_folder`, `transcripts_folder`). Outcomes are `#[serde(tag = "outcome", rename_all = "snake_case")]` enums (`FolderChange`). TS mirrors each one in `types.ts`, checks it with a guard in `guards.ts` (`isFolderChange`, `expecting`), and wraps the call in `commands.ts`. Events are named `area://thing` (`recording://started`).
- **Typed errors whose Display is the user text.** `LibraryError` → `report()` in `server.rs`. Errors use `thiserror` and never return sentinels.
- **Logging (ARCHITECTURE §5).** Log session ids and file names only (`file = %file_name(path)`). Never log pixels or paths built from user content.
- **AI-ergonomics (advisory).** Clippy runs `too_many_lines`, `cognitive_complexity` and `too_many_arguments` at deny, and ESLint enforces `complexity: 5` and `max-depth: 3`. `mcp_tools.rs` is 548 lines, so put the screenshot MCP tests in a new `tests/screenshots.rs`. `SettingsPanel` already takes 5 props, so give the shortcut section its own component and hook rather than widening the panel.

## 4c. Slice traps
- **Slice 5.1:** (1) Do NOT migrate or reshuffle flat and month-file sessions ([§10.4](004-screenshot-shortcuts.md#10-established-behaviour--documented-not-changed)). `existing_path` must try session → month → flat. (2) Look only inside folders whose names pass `SessionId::parse`, and only for `<id>/<id>.md` (AC 5.1.5). Never recurse, because the user may have picked `~/Documents`. (3) The collision probe moves to the **folder**: a candidate whose `<id>/` already holds a transcript goes on to `-2`. Keep `a_second_call_started_in_the_same_second_gets_its_own_file` green. Also skip a candidate id that already exists as a month or flat file, or the new folder will shadow it in `existing_path`. (4) A folder cannot be hard-linked. On POSIX, `fs::rename` onto an **existing empty directory succeeds**, so check that the destination is absent first, and copy across volumes into a `.part` folder before removing the source (AC 5.1.4). (5) Do NOT use `fs::create_dir_all`. Use `private_dir_builder`, and do not chmod a user-picked parent. (6) Moving is user-confirmed and non-destructive (`ask_to_move` in `transcripts_location.rs` is the project's only confirmation pattern; `count_transcripts` is its blast-radius count). Make `count_transcripts` count session folders as one each.
- **Slice 5.2:** (1) Take the offset from the **session's `SessionClock::elapsed()`**, the clock that stamps segments. Do NOT use `Local::now() - started_at`, or `tray_listener`'s `recording_since` (it starts later). (2) `RecordingController::stop` holds the recorder `Mutex` while it joins workers, which can take seconds. Do NOT block the shortcut handler on it. Stopping counts as "not recording" (AC 5.5.7). (3) Fix the destination, session id, offset and resolved session folder **at the press**. A recording that stops before save still saves there ([invariant 4.2](004-screenshot-shortcuts.md#4-invariants)). (4) No temp or staging file (AC 5.2.11): do NOT reuse `replace_atomically`. Write with a 0o600 `create_new` (bytes), and remove a partial file if the write fails, because a truncated PNG would still list. (5) The global-shortcut handler fires on **both Pressed and Released**. Act on `ShortcutState::Pressed` only. (6) ScreenCaptureKit's default output size is in **points**. Set the config width and height to points × scale (AC 5.2.4), and convert BGRA to RGBA before the clipboard and PNG. (7) Do NOT add `#[cfg(target_os)]`, `image` or Tauri types to `scribe-core`. The core `Frame` is plain width, height and RGBA bytes.
- **Slice 5.3:** (1) Do NOT append the section to the `.md` on disk ([§10.1](004-screenshot-shortcuts.md#10-established-behaviour--documented-not-changed)). Without screenshots, the response must be byte-identical to `document.raw` (AC 5.3.2). (2) Parse the reference as `SessionId` + `ScreenshotName` before any path join. Reject `..`, `\`, absolute paths, extra segments and non-`.png` names (AC 5.3.9). (3) Never upscale. Cap the long edge at 1568 even for newer models ([§10.2](004-screenshot-shortcuts.md#10-established-behaviour--documented-not-changed)). Write no scaled copy (AC 5.3.8). (4) `scribe-mcp` must not depend on a capture crate or `cidre`. CI's "MCP server stays free of audio and speech dependencies" step greps `cargo tree`. Image work belongs in `store-markdown`. (5) Update the exact-list assertion in `an_ai_app_discovers_…`, and include "Scribe" in the new description. (6) The 1 MB cap is for incoming messages only, so a served PNG may exceed it. Do NOT route outgoing data through `MAX_MESSAGE_BYTES`.
- **Slice 5.4:** (1) Check the permission with `preflight()` **before** capturing. On failure, write nothing and touch nothing on the clipboard. (2) `mac_notification_sys` blocks, so always send it on a spawned thread. (3) In `tauri dev`, TCC attributes the grant to the terminal. Release builds are ad-hoc signed (`"signingIdentity": "-"`), so a grant may not survive an update. Do not "fix" either in this slice. (4) Do NOT try to suppress the monthly re-confirm ([§9.1](004-screenshot-shortcuts.md#9-deferred-follow-ups-and-accepted-limits)).
- **Slice 5.5:** (1) Write nothing to disk, temp files included ([§10.3](004-screenshot-shortcuts.md#10-established-behaviour--documented-not-changed)). (2) Register the new route in `main.tsx` `ROUTES` and add the window label to `capabilities/default.json`, or the window shows the privacy statement and cannot invoke commands. (3) Build the window off the main thread. On Windows, building a webview window inside a **sync** command deadlocks, so use an async command or a spawned thread. (4) Keep "OK" focused on open. Esc and Enter close the notice; do not auto-focus the checkbox.
- **Slice 5.6/5.7:** (1) Capture the Frame and outlines **before** the selector opens, and crop from that Frame. Never re-capture (AC 5.6.10, [§9.2](004-screenshot-shortcuts.md#9-deferred-follow-ups-and-accepted-limits)). (2) Do NOT hand the Frame to the webview through a temp file or `convertFileSrc` ([invariant 4.5](004-screenshot-shortcuts.md#4-invariants)). Base64 JSON of a 5K frame (about 59 MB RGBA) blows the 500 ms budget. A binary IPC `Response` or a custom URI scheme needs a CSP `img-src`/`connect-src` change. (3) A second `app.manage(Mutex<BlurGuard>)` is silently ignored, and `BlurGuard` is popover-only. Give the selector its own guard and settle time. (4) Tauri `always_on_top` is the floating level, which sits **below the menu bar**, so AC 5.6.3 needs a raised NSWindow level and full-screen-auxiliary behaviour. (5) Validate the returned rectangle in Rust (positive size, inside the monitor) before cropping ([spec §6.1](004-screenshot-shortcuts.md#61-clean-code)). Map points to pixels with **that** monitor's scale (AC 5.6.11). (6) While the selector is open, ignore both shortcuts ([invariant 4.8](004-screenshot-shortcuts.md#4-invariants)). Exclude Scribe's own windows and layer ≠ 0 from outlines (AC 5.7.4).
- **Slice 5.8:** (1) `Popover.tsx` `useEscapeToHide` hides the popover on **every** Escape at the document level. While listening, Esc must cancel the rebind and must not hide the popover. (2) Read `event.code` (`Digit1`, `KeyA`), not `event.key`, because ⌥ changes `key` on macOS. (3) Unregister both shortcuts while listening, then re-register the old ones on cancel or failure, so the old binding keeps working (AC 5.8.5). (4) A bad stored binding falls back to the default with a warning and never fails launch (AC 5.8.9). (5) No shortcut switch-off ([§9.6](004-screenshot-shortcuts.md#9-deferred-follow-ups-and-accepted-limits)). (6) Register from Rust commands so no `global-shortcut:*` JS capability is needed. Do not widen capabilities.

## 5. Known dragons
- No `TODO`/`FIXME`/`LEGACY` markers in the walked modules.
- **Accessory activation policy** (`lib.rs` `run`): Scribe never becomes the active app on its own, so a new window may not take key focus. Esc, the pointer, and "switch away cancels" all depend on focus, so verify by hand.
- **Main-thread blocking:** shortcut and menu callbacks run on the event loop. `blocking_*` dialogs, `mac_notification_sys::send` and ScreenCaptureKit completion waits must stay off it. `transcripts_location.rs` gets away with `blocking_pick_folder` only because it runs inside an `async` command.
- **Recorder mutex held across stop/join** (`RecordingController::stop`, `stop_if_recording`). Any new caller of `state()` can stall for seconds.
- **Two store instances:** the tray manages one `Arc<MarkdownTranscriptStore>`. `scribe-mcp` uses `SettingsFollowingStore`, which re-reads `settings.json` per call. Screenshot reads must go through the following store.
- **`main.tsx` imports `popover.css` globally, and `body` paints `var(--surface)`.** A see-through selector needs its own `body:has(...)` override, like `body:has(.popover)` in `primitives.css`.
- **macOS 26 permission timing** ([spec §8.1](004-screenshot-shortcuts.md#8-open-questions)) and **undetected shortcut conflicts** ([§8.2](004-screenshot-shortcuts.md#8-open-questions), [§9.4](004-screenshot-shortcuts.md#9-deferred-follow-ups-and-accepted-limits)) are unresolved. Do not build retry loops around them.

## 6. Test conventions
- Rust: integration tests only, in `<crate>/tests/<topic>.rs`, with behaviour-sentence names (`a_second_screenshot_in_the_same_second_does_not_overwrite_the_first`). Arrange, act and assert are separated by blank lines. Each file has local helpers (`store_in`, `header_at`, `write_legacy_transcript`) and uses `tempfile::tempdir()`. Unix modes are checked under `#[cfg(unix)]` with `mode & 0o777`.
- Fakes: `scribe_core::testing` (feature `testing`): `InMemoryTranscriptStore`, `RecordingListenerSpy`, `FakeAudioSource`, `ScriptedTranscriber`. Add a `FakeScreenCapturer` and an in-memory screenshot store here so core and tray tests need no screen.
- MCP: `connect_to(folder)` over `tokio::io::duplex`, plus `call`, `text_of`, `is_tool_error`, and the recursive `folder_contents` (byte-identical check, AC 5.3.4/5.3.8).
- Tray: `src-tauri/tests/*.rs` against `pub mod`s only (`menu_action`, `transcripts_location`). Code that needs an `AppHandle` stays thin and untested, so keep binding validation and labels in pure `pub` functions.
- Timing budgets (AC 5.3.11, 5.6.2): `#[ignore = "timing budget: run by hand in release mode"]`, as in `scribe-core/tests/transcript_search_performance.rs`.
- OS smoke tests: `audio-macos/tests/tap_smoke.rs` and `stt-speechanalyzer/tests/live_smoke.rs` are the precedent for a capture smoke test that touches real hardware.
- Frontend: Vitest + testing-library + `vitest-axe`, co-located `*.spec.ts(x)`, `mockIPC` from `@tauri-apps/api/mocks`; `test-setup.ts` stubs `matchMedia`. Stryker mutates `src/**/*.{ts,tsx}`.
- Run order (CLAUDE.md): `stage-sidecar.sh` → `cargo fmt --all` → `cargo clippy --workspace --all-targets -- -D warnings` → `cargo test --workspace` → `npm run lint && npm test`. CI runs `cargo mutants --in-diff` and Stryker with `--enforce 75`. Linux CI runs only `PORTABLE_CRATES` (core, store-markdown, mcp…), so the core capture logic must build and test on Linux.

## 7. Hot paths and performance landmines
- `TranscriptStore::append` runs once per utterance. Do not add a folder scan or a settings read to `path_for` beyond one extra `is_file` probe.
- `list`/`list_all` run on every popover open and every MCP search. Session-folder discovery adds one `read_dir` per month, with no per-session `read_dir` beyond `<id>/<id>.md`.
- `get_transcript` lists screenshot names with one `read_dir` of the session folder. Never decode PNGs there.
- `get_screenshot` on 5K under 1 s (release): decode, resize once, encode. Do not clone full-resolution buffers more than needed.
- Shortcut → selector visible within 500 ms on 5K: the Frame transfer to the webview is the bottleneck (see trap 5.6 #2).

## 8. Open uncertainties resolved during orientation
- "Is `write_image` available?": yes. The locked `tauri-plugin-clipboard-manager` is 2.3.3, not the 2.5 the spec cites, and has `Clipboard::write_image(&Image)` on desktop.
- "Is `Content::image` available?": yes, in `rmcp` 3.5.1 `model/content.rs`. `scribe-mcp` needs its own `base64` dep (several versions are already in the lock).
- "Does `cidre` cover capture and the permission?": yes. It has `sc::ScreenshotManager::capture_image` (macOS 14+), `capture_image_in_rect` (15.2+) and `cg::screen_capture_access::{preflight, request}`. `audio-macos` enables none of these features yet.
- "Can the tray learn the session offset today?": no. The session clock is private to `SessionWriter`, so `Recorder` needs a narrow accessor for the active id and elapsed time.
- "Global shortcuts": the plugin is not a dependency yet. Register from Rust so the change stays out of the capability file.
- **Left for the plan:** whether `get_screenshot` refuses sessions still `recording`, as `TranscriptLibrary::get` does, and where flat or month-file sessions land when the user moves folders (today they become month files; [§10.4](004-screenshot-shortcuts.md#10-established-behaviour--documented-not-changed) forbids only *automatic* migration).
