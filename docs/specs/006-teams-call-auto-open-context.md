**No spec file exists**, so this file cites no spec anchors. The slices below follow the natural seams of the brief. If the plan slices the work differently, map its slices onto these.
- **A** a pure core latch. It is fed "does a Teams process hold the mic?" plus a time, and it says "call started" exactly once per call (rising edge). It stays latched until the mic has been released for a grace period.
- **B** macOS probe: Core Audio process objects (`cidre`), Teams = bundle id prefix `com.microsoft.teams2`, with `is_running_input`.
- **C** Windows probe: WASAPI capture-endpoint audio sessions (`wasapi`), owning pid resolved to `ms-teams.exe` (or a `msedgewebview2.exe` whose parent is `ms-teams.exe`).
- **D** tray wiring: a background poll thread. On the rising edge, if the recorder is not `Recording`, the popover is shown without toggling.

**De-facto style:** Hexagonal (ADR 1 in `docs/ARCHITECTURE.md`). The latch is domain logic and goes in `scribe-core` (portable, so Linux CI and mutation testing cover it). Process and audio-session inspection is OS edge code and goes in the adapter crates, which already link `cidre`/`wasapi`. Polling and showing the popover go in `apps/scribe-tray`. ARCHITECTURE §7 rules apply: no `#[cfg(target_os)]` in core, no Tauri types below `apps/`, and no shared mutable singletons.

## 2. Patterns to follow
- **Pure judge, time passed in, no clock inside.** In core: `QuietWatch::hear_through(Duration)` + `is_report_due()` (`quiet_watch.rs`). In the tray and adapters: `BlurGuard::blur_should_hide(now: Instant)` and `ChangeDebounce::take_settled(now: Instant)`. Tests build times as `opened + Duration::from_millis(..)`. Nothing sleeps.
- **Report once, re-arm on a real change** (`QuietWatch.reported` + `mark_reported`, `SilenceWatchdog.reported`). Rising edge = report on the false→true transition only.
- **Named threshold consts at the top of the module** (`AUTO_STOP_AFTER_QUIET`, `SETTLE`, `SETTLE_TIME`, `TICK`, `DELIVERY_INTERVAL`).
- **Adapter crate gating:** `lib.rs` puts `#[cfg(target_os = "macos")]` (or `#[cfg(windows)]`) on every `mod` and `pub use`, so the crate compiles empty elsewhere (`audio-macos/src/lib.rs`, `audio-windows/src/lib.rs`). Files that call FFI start with `#![allow(unsafe_code)]` (the workspace denies `unsafe_code`).
- **Adapter errors map to the core port error** through a small `failure(action, status)` / `stream_failed(&error)` helper (`tap.rs`, `stream.rs`).
- **Background work in the tray:** `thread::spawn` with a cloned `AppHandle`, and state reached through `app.state::<T>()` (`recording::start_in_background`, `model_setup::spawn_attempt`, `screenshots::shortcuts::capture_in_background`). A thread that lives as long as the app loops on `recv_timeout` (`TrayUpdater::run`), so the wait doubles as a stop signal. A thread with an owned lifetime is a `{ stop: Sender<()>, thread: JoinHandle<()> }` pair with `stop()` → send + join (`audio-windows/src/capture.rs` `Capture`).
- **Tray failures are logged, never propagated to the UI thread:** `log_failure(outcome, "could not …")` with `tracing::warn!(%error, ..)` (`popover.rs`, `tray.rs`).
- Advisory (ai-ergonomics): `testing.rs` is large (579 lines). Keep the new fake to a few lines. `notifications.rs` is 312 lines, so do not route this feature through it.

## 4c. Slice traps
- **Slice A:** (1) do NOT call `Instant::now()`/`SessionClock` inside the latch. Take the time as a parameter, so the tests simulate time. (2) report only on false→true. A `true` poll while latched must not report again. Mic-off shorter than the grace (Teams mute or device switch) must not unlatch. (3) do NOT put Teams names, bundle ids or `cfg` in core (§7). (4) a probe `Err` must not count as "mic released", or a transient Core Audio error would re-arm the latch mid-call. Decide explicitly (e.g. treat it as "no change").
- **Slice B:** (1) do NOT match a bare `com.microsoft.` prefix: Edge (`com.microsoft.edgemac`), Outlook and Word would match. Browser Teams is out of scope. (2) `bundle_id()` can fail or be empty for helper or CLI processes. Skip those, do not error the whole poll. (3) skip Scribe's own process (`own_process_object` / `std::process::id()`), even though its bundle id differs. (4) use `is_running_input`, not `is_running`/`is_running_output` (ringing plays output before any mic use).
- **Slice C:** (1) do NOT match `msedgewebview2.exe` by name alone. Widgets, Outlook and many apps host WebView2. Require that its parent (or ancestor) is `ms-teams.exe`. (2) the default capture device in Console role may not be the mic Teams uses. Enumerate all active capture endpoints (`get_device_collection(&Direction::Capture)`), or at least include the `Role::Communications` default. (3) iterate with `get_nbr_devices`/`get_device_at_index`, not `for d in &collection`: `DeviceCollectionIter::next` `unwrap()`s `get_nbr_devices`. (4) COM: call `initialize_mta()` on the polling thread itself and `deinitialize()` on exit. Never probe from a Tauri command thread. (5) only `SessionState::Active` counts. `Inactive` sessions linger after a call.
- **Slice D:** (1) do NOT call `popover::toggle`, because it **hides** a visible popover. Add a non-toggling entry point. (2) `show` starts with `move_window_constrained(Position::TrayCenter)?`, which returns `Err("Tray position not set")` until the user has clicked or hovered the tray icon since launch (`tauri_plugin_positioner::on_tray_event` only records the tray rect on `Click`/`Enter`/`Leave`/`Move`). An auto-open before any tray interaction would silently do nothing. Seed the position from `app.tray_by_id(TRAY_ID)?.rect()`, or fall back. (3) call `guard.shown(now)` (via `show`) so the 300 ms `SETTLE` covers the focus bounce. If Teams re-takes focus after 300 ms, blur-hide will still close the popover (see dragons). (4) check `RecorderState` only on the rising edge, not on every poll. `state()` locks `Mutex<Recorder>`, and that mutex is held for seconds during `stop` (it joins workers). (5) do NOT add a `RecordingEvent` variant or reuse `TrayRecordingListener`: a Teams call is not a recording event. (6) install after `popover::install_blur_hide` in `start_scribe`, because `with_guard` panics if `Mutex<BlurGuard>` is not managed yet.

## 5. Known dragons
- **Focus from a background trigger (macOS):** tao `set_focus` = `makeKeyAndOrderFront` + `activateIgnoringOtherApps: YES` (deprecated since macOS 14; the app's minimum is macOS 26). Under cooperative activation the Accessory app may not become active while Teams is frontmost. The popover would then show (`alwaysOnTop`) without key focus, so no `Focused(false)` arrives and blur-hide never fires until the user clicks it. Or Teams' own call window grabs focus right after, and the popover blur-hides after 300 ms. **Verify on hardware.** This is the spike's main risk. On Windows, tao uses `force_window_active` (an Alt-key trick), so the popover is likely to steal focus from Teams.
- `privacy::show_statement`, `idle_notice::show` and `region_selector::open` all `set_focus` new windows. `region_selector::cancel_on_blur` ignores blur until it has seen `Focused(true)` (`has_been_focused`). That is a precedent if the popover needs "ignore blur until really focused".
- The Windows CI job runs **clippy only, no tests** (ADR 2). Windows probe logic is therefore never executed in CI, which is a reason to keep the decision logic in core and the adapter thin. The macOS job lists crates explicitly (`-p scribe-tray -p audio-macos …`). A **new** crate must be added to the `macos`/`windows` job lines, not to `PORTABLE_CRATES` (which is only for platform-neutral crates). Reusing `audio-macos`/`audio-windows` avoids touching CI.
- The CI guard forbids `scribe-mcp` from depending on `cidre|cpal|wasapi|xcap|audio-*|capture-*`. Keep the probe port in `scribe-core` free of those dependencies.
- `mutants.toml` excludes the Tauri-bound tray files (`lib.rs`, `notifications.rs`, `screenshots/*`). A new Tauri-bound poller file will produce uncaught mutants unless it is kept trivial or excluded the same way.
- Background threads in the tray are never joined on quit. `tray::quit` → `app.exit(0)`. The power observers are deliberately leaked (`keep_observing_for_the_app_lifetime`, `Box::leak`). A poller that lives as long as the app is consistent with that. Do not add a shutdown mechanism the app has no hook for.
- There are no `TODO`/`FIXME`/`LEGACY` markers in first-party code.

## 7. Hot paths and performance landmines
- The poll runs for the whole app lifetime, including on battery. Keep the interval at 1 s or more. On macOS, read `bundle_id` only for processes whose `is_running_input` is true (or the reverse, whichever is cheaper), rather than every property of every process. On Windows, only `OpenProcess` the pids of `Active` sessions.
- `RecordingController::state()` contends with `start`/`stop` on `Mutex<Recorder>`. Call it once per rising edge only.
- Popover `show` goes through the Tauri main thread (`run_on_main`). Do not call it every poll tick.

## 8. Open uncertainties resolved during orientation
- **Mic permission:** reading Core Audio process objects (`kAudioHardwarePropertyProcessObjectList`, `PROCESS_IS_RUNNING_INPUT`) and enumerating WASAPI sessions open no stream, so `audio-mic::permission` is not involved. This is not verified against TCC on macOS 26; confirm in the spike.
- **Placement:** `audio-macos` already enables `cidre`'s `core_audio`, and `audio-windows` already links `wasapi`, so both probes fit there with no new crate and no CI change. The latch goes in `scribe-core` (portable CI plus mutation). The tray only polls and shows.
- **Polling vs listening:** both are possible on macOS (`add_prop_listener` on `HW_PROCESS_OBJ_LIST` plus per-process `PROCESS_IS_RUNNING_INPUT`). Polling is simpler and identical across both OSes. Windows session events (`register_session_notification`) are per session. Polling is the MVP choice.
- **Still open for the plan:** (a) the exact Teams helper bundle ids on macOS, and whether audio I/O runs in the main `com.microsoft.teams2` process or a helper. (b) whether new Teams on Windows owns the capture session itself or through a `msedgewebview2.exe` child. `get_session_identifier()` often embeds the exe path, which may be a cheaper resolver than `OpenProcess`. (c) the pre-join screen's mic preview will fire the rising edge before the call is joined; accept it or not? (d) open when `RecorderState::Locked` (model downloading, privacy not acknowledged), or only when `Idle`? (e) grace length (suggested 20 to 60 s) and whether a setting is needed (YAGNI: a constant).
